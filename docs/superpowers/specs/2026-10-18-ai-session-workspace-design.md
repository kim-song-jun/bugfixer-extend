# AI 세션 작업공간 설계

상태: 사용자 요청을 현재 코드와 대조한 구현 설계 초안. 2026-10-18. 기존에 승인된 기반·계정·프로젝트 창·작업 상태 정책은 유지한다. 병렬 수정의 기본 작업 폴더 방식은 아래 결정에서 선택한다. 이 문서는 구현 완료 증거가 아니다.

## 사용자가 하려는 일

한 프로젝트에서 Codex와 Claude의 여러 터미널 세션을 열고, 모델과 역할을 나누어 일한다. 사용자는 각 세션이 무엇을 하는지, 어디서 막혔는지, 어떤 파일을 어떤 근거로 수정했는지 바로 확인한다. 세션들은 MCP를 통해 서로 일을 요청하고 결과를 전달한다. 변경 내용을 사람이 검토하고 확인한 뒤에만 GitHub PR을 만든다. 첫 실행부터 이 흐름을 이해할 수 있는 한글 온보딩을 제공한다.

## 보존하는 결정과 확인된 현재 상태

- Whiteboard/Code OSS 셸과 별도 `workspace.db`, 프로젝트마다 네이티브 창, 대시보드·파일·리뷰 탭을 보존한다.
- 한글, Pretendard, 현재 공개용 POSCO-MLIP 유래 일반 테마 토큰, 평평한 행·구분선 중심 구조를 쓴다. 카드 안에 카드를 반복하지 않는다. 비공개 Molcube/POSCO 자료를 포함하지 않는다.
- Codex와 Claude부터 구현한다. 현재 선택된 계정 모드는 공급자마다 기존 로컬 CLI 프로필 하나다. 여러 세션과 여러 계정은 별개이며, 계정 격리 검증 전에는 다중 계정 지원으로 표시하지 않는다. `agy`와 Windows는 기존의 후속 단계다.
- 기존 `workspaceProviderRunsChannel`과 공급자 어댑터는 단발 headless 작업 실행, 실행 ID/이벤트, 하위 실행과 프로세스 정리를 제공한다. 지속 대화형 PTY 세션, 세션 우편함, 세션 제어 MCP, PR 승인 흐름은 아직 없다.
- 기존 단발 실행의 대상 폴더 식별·단일 수정자 잠금·사람이 Done을 결정하는 정책은 새 세션에서도 유효하다. 작업 성공과 PR 승인은 서로 다른 기록이다.
- 빌드·typecheck·lint·테스트·검증 스크립트는 GitHub CI에서 실행한다. 로컬은 편집과 가벼운 읽기 및 증거 확인에 사용한다.

## 1. 세션과 실행을 구분한다

`AgentSession`은 사람이 이름을 붙여 계속 사용하는 작업 자리다. 공급자, 모델, 계정 참조, 프로젝트, 선택한 작업, 역할, 작업 폴더, 상위 세션, 권한 정책을 가진다. 앱 세션 ID와 공급자의 대화 ID를 구분한다. 한 번의 실행·재개는 별도 `SessionTurn`으로 남기고 기존 기록을 덮어쓰지 않는다.

세션 상태는 준비, 시작 중, 실행 중, 입력 대기, 승인 대기, 유휴, 중단 중, 종료, 중단됨, 실패로 구분한다. 실제 provider lifecycle 신호가 없는 일반 터미널 출력만으로 성공·유휴·입력 대기를 추정하지 않는다. 확인되지 않은 상태는 그 이유와 함께 표시한다. 연결과 실행 종료, 작업 완료를 같은 상태로 합치지 않는다.

대화형 CLI는 Code OSS의 실제 PTY/터미널을 사용한다. 터미널의 입력·리사이즈·복사·검색·붙여넣기·스크롤을 유지하며 단발 JSON 실행 화면을 터미널로 가장하지 않는다. 세션 전환으로 프로세스가 다시 시작되지 않는다. 종료 시 앱이 소유한 프로세스·PTY·도구·작업 복사본의 정리 결과를 남긴다. 재시작 후 프로세스 소유권을 증명하지 못하면 중단됨으로 표시하고 명시적으로 새 turn을 시작한다.

모델은 공급자별 지원 ID를 선택하고 실제 실행 값으로 기록한다. 표시 이름만 바꿔 다른 모델을 실행하지 않는다. 인증 실패나 없는 모델을 다른 공급자·계정·과금 경로로 바꾸지 않는다. 프로필·버전·모델·권한·규칙·참고자료의 실행 스냅샷을 보관한다.

## 2. 화면: 작업과 세션을 바로 연결한다

프로젝트 탐색에 **AI 세션**을 추가하고 네이티브 편집기 탭으로 연다. 대시보드의 진행 중 작업과 알림에서 정확한 세션으로 이동한다. 프로젝트 창 안에서 세션 선택이 다른 프로젝트의 세션을 조작하지 않는다.

세션 화면은 세션 목록과 선택한 세션의 본문으로 구성한다. 목록에는 이름, 공급자/모델, 현재 작업, 상태, 읽지 않은 메시지·승인 요청만 표시한다. 본문 상단에는 현재 작업과 실행/중단 동작, 그 아래에는 **터미널 · 변경 내역 · 로그** 탭을 둔다. 메시지와 알림은 필요할 때 여는 보조 패널이다. 워크플로는 상위 세션의 위임 목록과 의존 관계로 보되 기본 화면을 그래프 편집기로 만들지 않는다.

빈 화면에는 세션 만들기, 로딩에는 자리 표시, 실패에는 원인과 재시도, 연결 끊김에는 마지막 저장 시각과 재연결, 승인 대기에는 검토할 범위와 거절/승인을 제공한다. 좁은 창에서는 세션 목록을 선택기로 줄이고 본문 폭을 확보한다. 현재 세션, 포커스, 스크롤 위치를 복원한다. 세션 생성·전환·중단·메시지 열기·알림 이동·변경 검토가 키보드로 가능해야 한다.

## 3. 로그와 알림

구조화된 실행 이벤트와 터미널 출력은 구분해 보관한다. 로그는 세션/turn/시간/심각도/출처로 찾고, 실시간 따라가기·일시 정지·검색·복사·내보내기를 제공한다. 로그를 보려고 원본 터미널을 계속 열어둘 필요가 없어야 한다. 이벤트 순서 번호와 저장 커서를 사용해 재연결 시 중복·누락을 확인한다. 출력은 청크로 저장하고 페이지 단위로 읽어 대량 출력이 렌더러 메모리를 고갈시키지 않는다.

기존 비밀정보 정책을 적용한다. 토큰·인증 헤더·키·계정 파일 본문은 화면과 디스크 기록 전에 마스킹한다. 마스킹과 저장 범위는 UI에 설명한다. 보존 기간·용량과 삭제는 설정에서 확인하며, 삭제/한도 때문에 빠진 구간은 빈 구간으로 표시한다. 조용히 잘라낸 뒤 전체 로그라고 표시하지 않는다. 원문 복사 기능이 비밀정보 마스킹을 우회하지 않아야 한다.

앱 알림함은 입력/승인 요청, 실패, 완료, 새 메시지, PR 검토 준비를 저장한다. 중복 알림은 동일 이벤트 ID로 합치고 읽음 상태를 유지한다. 클릭하면 해당 프로젝트·세션·turn·변경으로 이동한다. 운영체제 알림은 사용자 설정과 macOS 권한에 따라 선택적으로 제공하며 인증값·소스 본문을 포함하지 않는다. 알림 거절이 앱 내부 기록을 막지 않는다.

## 4. 세션 간 통신과 MCP 오케스트레이션

Codex↔Claude, Codex↔Codex, Claude↔Claude는 공급자 조합과 관계없이 같은 앱 세션 ID로 통신한다. `SessionMessage`는 보낸/받는 세션, 프로젝트, 메시지 ID, 원인 메시지 ID, 본문, 선택한 참고자료/산출물 참조, 생성·전달·읽음 시각을 가진다. 발신 idempotency key와 수신 cursor/ack로 재시도 중복과 재시작 손실을 막는다. 상대가 종료/실패한 경우 전달 불가 또는 대기로 명시한다.

메시지는 앱의 지속 우편함으로 전달한다. 실행 중인 터미널에 문자열을 임의로 입력하지 않는다. 에이전트는 MCP에서 받은 메시지를 읽고 ack한다. 승인된 워크플로에서 유휴 세션의 다음 turn을 시작하는 경우에는 메시지와 실행 사유를 먼저 turn 기록에 남기고 공급자의 지원되는 재개 방식으로 전달한다. 대기 중 전달과 실제 읽음을 구분한다. 작업 외부의 메시지는 프로젝트 권한을 자동으로 넓히지 않으며 기본 수신 범위는 같은 프로젝트다.

앱의 메인 프로세스가 세션, 작업, 우편함, 실행 정책을 소유한다. MCP는 같은 서비스에 접근하는 인터페이스이며 별도 실행 엔진이 아니다. 앱이 각 CLI 실행에 한정된 MCP 설정과 프로젝트/세션/권한 토큰을 주입한다. 사용자의 전역 Codex/Claude 설정·계정 파일을 바꾸지 않는다. 토큰은 로그/SQLite 본문에 기록하지 않고 종료·권한 철회 시 무효화한다.

MCP는 세션/작업 조회, 허용된 하위 세션 요청, 메시지 송수신/대기, 로그·산출물·변경 근거 조회, 워크플로 상태/취소, PR 검토안 준비를 제공한다. MCP가 사람의 권한 승인이나 PR 승인을 위조·대신할 수 없다. 외부 MCP 클라이언트 연결은 앱이 발급한 프로젝트 범위 권한으로만 허용한다.

워크플로는 역할·공급자·모델·작업·선행 단계·공유할 참고자료·권한·최대 동시 수·최대 실행/시간을 가진 유한한 계획이다. 실행 전에 사람이 계획과 수정 범위를 확인한다. 승인된 범위 안의 읽기/위임/메시지는 자동 진행하고, 새 수정 대상·권한·외부 쓰기는 승인 대기로 전환한다. 승인된 계획을 바꾸면 새 버전으로 기록한다. 실패·취소·한도 초과는 하위 실행에 전파하고 정리 실패를 드러낸다. 공급자 내부 helper를 앱이 관리하는 별도 세션으로 허위 표시하지 않는다.

## 5. 변경 내역과 수정 근거

각 파일 변경은 원래 내용/결과의 해시, 기준 commit 또는 폴더 스냅샷, 파일 경로, 세션/turn, 명령·도구 이벤트, 확인된 시간 범위를 연결한다. diff는 파일별·변경 구간별로 열고 추가/수정/삭제/이름 변경을 구분한다. 일반 폴더도 기준 스냅샷으로 비교하되 수집 범위 밖 변경을 없었다고 주장하지 않는다.

변경 설명에는 **무엇을 바꿨는지 / 왜 바꿨는지 / 근거 / 검증 결과**를 둔다. 에이전트의 설명은 해당 diff와 참고자료·규칙·이벤트를 참조해야 한다. 근거 없는 설명은 ‘근거 미연결’, 사람이 바꾼 부분은 ‘세션 미지정’으로 보여 준다. 실제 터미널 변경을 관찰했다는 사실만으로 모델의 내부 추론을 안다고 주장하지 않는다. 사용자에게 보여줄 설명과 확인 가능한 근거를 기록한다. 사용자가 내용을 정정하고 검토 상태를 남길 수 있다.

변경 후 diff가 달라지면 이전 검토/승인을 유효하게 재사용하지 않는다. 이전 버전과 검토 이력은 보존한다. 공급자의 도구 결과와 사용자가 편집기로 한 변경이 섞여도 출처를 거짓으로 단정하지 않는다.

## 6. PR 전 확인

Whiteboard 리뷰와 GitHub PR을 구분한다. 세션은 PR 검토안을 준비할 수 있다. 검토안에는 저장소·대상 base·작업 branch·선택한 파일·정확한 diff fingerprint·기준/현재 HEAD·수정 근거·실행한 검증과 미검증 항목·제목/본문을 담는다. 사용자는 파일별 내용을 확인하고 고친 뒤 **승인하고 PR 생성**을 누른다. 에이전트/MCP는 이 승인을 호출할 수 없다.

승인 직전과 외부 쓰기 직전에 현재 diff/HEAD를 다시 검사한다. 바뀌면 기존 승인을 만료시키고 새 변경을 보여 준다. commit/push/PR 생성에 필요한 동작·대상 원격·공개 범위를 같은 승인 화면에 정확히 표시한다. 범위 밖 변경을 stage하거나 기존 사용자 branch를 전환하지 않는다. 실패 시 실제로 완료된 단계와 원격 PR/commit ID를 기록해 재시도가 중복 PR을 만들지 않게 한다. 삭제·자동 병합·강제 push는 이 승인에 포함하지 않는다.

## 7. 온보딩

첫 실행의 한글 단계는 프로젝트 선택 → 설치된 CLI와 계정 상태 확인 → 세션/모델 선택 → 권한·작업 폴더·규칙 확인 → 첫 작업이다. Slack/Notion/커넥터는 나중에 연결할 수 있다. 로그인은 공급자의 공식 흐름을 열고 앱이 비밀번호를 수집하지 않는다. 설치되지 않은 CLI는 경로와 설치 안내를 보여 주며 다른 공급자로 바꾸지 않는다. 읽기만 하는 점검과 실제 비용이 발생할 수 있는 첫 실행을 구분한다.

MCP 연결 상태, 세션 간 공유 범위, 알림 권한, 로그 마스킹, 중단/복구 방법을 실제 첫 작업에서 짧게 안내한다. 온보딩은 건너뛰기·재개·설정에서 다시 열기가 가능하고 여러 프로젝트를 만들 때 계정 설정을 반복 입력하게 하지 않는다. 예시 데이터와 실제 프로젝트 기록을 혼합하지 않는다.

## 8. 남은 사용자 결정: 병렬 수정의 작업 폴더

공유 폴더에서 읽기 세션 여러 개는 동시에 실행할 수 있다. 같은 정식 경로를 수정하는 세션은 기존 잠금으로 직렬화한다. 이를 숨기거나 잠금을 없애 병렬 수정처럼 보이게 하지 않는다.

- A — 현재 프로젝트 폴더 공유: 같은 폴더의 수정 실행은 대기한다. 단순하고 사용자의 파일이 바로 바뀐다.
- B — 세션별 작업 복사본: Git 프로젝트는 앱이 소유한 worktree/branch에서 병렬 수정하고, 검토 후 사용자 프로젝트/PR에 반영한다. 추천: 여러 AI가 서로의 진행 중 파일을 덮어쓰지 않고 각각의 diff와 근거를 보존할 수 있다. 저장공간·합치기 충돌 UI·수명주기 관리가 추가된다. 일반 폴더는 기존 단일 수정자 정책을 유지한다. jj는 검증된 별도 workspace 지원 전까지 공유 폴더 정책을 명시한다.
- C — 시작할 때마다 선택: 공유 폴더와 격리된 Git 작업 복사본 중 사용자가 선택한다. 유연하지만 매번 선택과 의미 설명이 필요하다.

이 선택은 PR 흐름과 세션의 파일 편집 위치에 영향을 준다. 기존 리뷰 DB, 커넥터, 규칙과 계정 선택을 변경하지 않는다. 어느 선택이든 프로세스/폴더 소유권과 복구되지 않은 변경은 삭제하지 않는다. B/C를 구현할 때 사용자 branch를 자동 전환하지 않고 앱 소유 ref만 만든다.

## 9. 구현 순서와 완료 증거

1. 세션/turn/로그 청크/메시지/알림의 별도 DB 스키마와 프로젝트 범위 서비스, 기존 실행과의 연결을 만든다. 세션 ID, 순서, 중복, 재시작, 다른 프로젝트 접근 거부를 CI에서 검증한다.
2. 실제 터미널 연결과 한글 AI 세션 탭을 만든다. 실제 PTY fixture로 입력·출력·리사이즈·전환·종료·대량 출력·프로세스 정리를 CI에서 확인한다. 공급자 조합과 모델 설정을 이어 붙인다.
3. 세션 범위 MCP와 우편함, 승인된 워크플로 실행을 만든다. 세 공급자 조합의 왕복, 종료된 수신자, 중복/순서, 취소, 권한 위조, 한도와 토큰 철회를 CI에서 검증한다.
4. 변경/근거/검증 증거와 PR 검토/승인/재시도 상태를 연결한다. 승인 후 파일 변경·HEAD 변경·원격 실패·중복 재시도·범위 밖 staging을 검증한다.
5. 통합 알림과 온보딩을 연결하고, 밝은/어두운 테마 및 넓은/좁은 창에서 실제 화면과 키보드 흐름을 확인한다. 현재 앱의 기존 기능도 이어서 검수한다.

테스트용 CLI fixture는 실제 프로세스/PTY/DB/MCP 경계를 검증하지만 실제 Codex/Claude 인증·모델·구독 동작의 증거로 세지 않는다. 실제 CLI 두 개의 동시 실행, 각 공급자 조합 통신, 지원 모델, 취소·재개·종료 정리는 인증된 환경에서 별도로 증명해야 한다. 실행하지 않은 검증은 실행했다고 표시하지 않는다. 모든 요구가 구현되고 해당 범위의 증거가 확보되기 전에는 전체 완료로 보고하지 않는다.

## 확인한 구현 지점과 공식 문서

- 앱 서비스 등록과 종료: `whiteboard/apps/review-desktop/code-oss/src/vs/code/electron-main/app.ts`. 기존 실행: `src/vs/workspace/electron-main/workspaceProviderRunsChannel.ts`, `providerRuns/`. 기존 영속 저장소: 같은 디렉터리의 `workspaceDatabase.ts`.

- 기존 Whiteboard MCP: `whiteboard/packages/review/src/review-api/mcp.ts`. 이 서버의 리뷰 도구만으로 앱 세션 제어가 구현됐다고 간주하지 않는다.
- [Codex CLI 명령](https://learn.chatgpt.com/docs/developer-commands?surface=cli)과 [MCP 설정](https://learn.chatgpt.com/docs/extend/mcp?surface=cli): 모델·설정 override, 명시한 대화 ID의 interactive resume, stdio 서버 command/args/env 전달을 확인했다. 현재 설치 버전의 지원과 실제 전달은 별도 실행 검증이 필요하다.
- [Claude CLI 명령](https://code.claude.com/docs/en/cli-reference)과 [MCP 설정](https://code.claude.com/docs/en/mcp): 세션별 모델, 명시한 ID/name의 resume, 실행별 `--mcp-config`와 `--strict-mcp-config`를 확인했다. 실제 세션 lifecycle 수집은 별도 어댑터 검증이 필요하다.
