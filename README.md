# Bugfixer Extend

프로젝트별 작업 보드에서 에이전트에게 일을 전달하고 실행·검증 결과를 확인하는 VS Code 기반 작업 워크스페이스를 기획 중입니다.

선택한 기반은 Whiteboard의 Code OSS 데스크톱 앱입니다. 프로젝트별 작업 보드와 에이전트 실행은 Bugfixer의 개념을 참고해 앱 안에 범용 기능으로 새로 설계합니다. 비공개 Bugfixer 저장소의 파일·데이터를 그대로 복사하지 않습니다. 프로젝트·작업 데이터는 앱의 별도 `workspace.db`에 저장하고 Whiteboard 리뷰는 반환된 리뷰 ID로 연결하는 설계를 선택했습니다.

첫 화면은 posco-mds의 라이트·다크 테마 원칙을 참고한 간결한 프로젝트 대시보드입니다. 편집 가능한 Code OSS 프로젝트 창에서 대시보드·파일·Whiteboard 리뷰를 같은 창의 탭으로 여는 설계를 선택했습니다.
여러 프로젝트는 프로젝트마다 네이티브 창을 두고, 전환할 때 해당 창을 앞으로 가져오거나 새로 엽니다. 탭과 선택한 작업은 각 프로젝트 창에 남습니다.

프로젝트별 컨벤션은 앱 설정의 읽기 좋은 버전 문서로 관리합니다. 에이전트가 선택한 레퍼런스로 초안을 쓰고 별도로 검수하며, 사용자가 근거·예시를 읽고 적용한 버전만 작업 실행에 주입합니다. Slack·Notion·웹사이트 자료 가져오기를 기본 제공하고, 첫 공개 버전에서는 앱이 해석하는 선언형 커넥터를 사용자가 설치해 출처가 보존된 자료를 작업·근거에 연결하는 설계를 선택했습니다. 설치한 패키지의 임의 코드는 실행하지 않습니다. 이 범용 기능은 새로 구현할 대상입니다.

Mobius의 계정 관리 경험을 참고하되, 지원하는 에이전트 실행은 검증된 계정별 프로필에 고정해 다른 실행의 인증 상태를 바꾸지 않도록 설계합니다. ego-lite의 브라우저 E2E도 작업 실행·증거에 연결할 대상입니다.

첫 제품은 macOS에서 사용하고 Windows 지원은 이후 단계에서 진행합니다. 요청하신 Windows x86이 32비트 x86인지 x86-64인지는 아직 확정하지 않았습니다.

현재 기능과 새 제품에서 구현할 범위는 [발견 기록](docs/discovery.md)에, 확정한 데이터 경계는 [아키텍처](docs/architecture.md)에 정리했습니다. 첫 macOS 작업 경험은 보관·정렬·여러 리뷰·삭제·실제 에이전트 실행을 포함하는 [C 범위](docs/first-macos-task-scope.md)로 선택했습니다. 실행 시작 시 In progress, 검증된 성공 시 Review로 자동 이동하고 Done은 사람이 선택합니다. 실행 중인 작업 삭제는 그 작업의 에이전트 실행을 취소·정리한 뒤 휴지통으로 보내며 복원할 수 있습니다. 리뷰가 여러 개면 사람이 주 리뷰를 선택하고, 새 리뷰는 기본 열기 대상을 바꾸지 않습니다. Git/jj가 없는 폴더에서도 폴더별 수정 허용과 실행할 에이전트의 실제 권한 범위 표시 후 파일을 수정할 수 있습니다. 이때 Review 상태는 사람이 변경 내역과 파일을 확인하는 단계이며 Whiteboard 문서가 생긴다는 뜻은 아닙니다. 프로젝트 창·작업 보드·리뷰 연결의 [내부 기반 검증 단계](docs/foundation-checkpoint.md)는 이 범위의 시작일 뿐이며, 설계 승인이나 구현 완료를 뜻하지 않습니다.

전체 제품의 완료 기준과 현재 빠진 실행 증거는 [제품 수용 증거표](docs/product-acceptance.md)에 모았습니다.
원본 Whiteboard가 내려받는 확장 프로그램의 고정 버전과 배포 전 라이선스·고지 확인 항목은 [확장 프로그램 배포 목록](docs/extension-distribution.md)에 정리했습니다.
